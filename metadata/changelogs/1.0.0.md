# 1.0.0

Initial release.

## Added

- **Fluid fuel data map** (`justdirefuels:fluid_fuels`) keyed by fluid id with an `fe_per_mb` value. Any fluid in the map is a valid Fluid Generator T1 fuel, replacing JDT's `instanceof RefinedFuel` check and the three hardcoded config values.
- **Item fuel data map** (`justdirefuels:item_fuels`) keyed by item id with optional `fe_per_tick` and `burn_speed_multiplier` values. Lets datapacks override JDT's Solid Generator T1 per-fuel rates without touching server config.
- **JEI category** "Fluid Generator Fuels" listing every fluid in the data map with its FE/mB rate. Fluid Generator T1 is the recipe catalyst.
- **Default data map entries** mirroring JDT 1.5.7's stock config values so behavior is identical out-of-the-box (T2=450, T3=1300, T4=4000 FE/mB; Coal_T1..T4 burn-speed multipliers 2/4/8/16).
- **Sample datapack** at `examples/justdirefuels_demo/` demonstrating new fluid fuels, value overrides, and new solid fuels in a single drop-in pack.

## Technical

- Five mixins against JDT internals:
  - `GeneratorFluidT1BE` — scopes the expanded tank validator to the current Fluid Generator T1 tank attachment and performs the data-map FE/mB lookup with fallthrough to original `RefinedFuel` behavior.
  - `BaseMachineBE#loadAdditional` — restores that validator after NeoForge deserializes and replaces the saved tank attachment, while ignoring every other JDT machine.
  - `GeneratorFluidItemHandler#isItemValid` — accepts buckets/containers of any data-map fluid.
  - `RefinedFuelSlot#mayPlace` — accepts data-map fluid containers in the generator GUI.
  - `GeneratorT1BE` — captures per-burn data-map values at burn start, persists across world reload via `saveAdditional`/`loadAdditional` injection, and serves them from `getFePerFuelTick`.
- Mixin injectors fail fast when a required JDT target is missing instead of silently skipping the integration.
- Data maps registered via `RegisterDataMapTypesEvent` on the mod bus, synced to clients for JEI display.
